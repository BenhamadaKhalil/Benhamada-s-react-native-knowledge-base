## 📱 React Native – Platform-Specific Code & Styling

### 1️⃣ Detecting Platform Dynamically

React Native exposes a **Platform API**:

```js
import { Platform } from "react-native";

borderWidth: Platform.OS === "android" ? 2 : 0
```

- `Platform.OS` returns a string:
    
    - `"ios"`
        
    - `"android"`
        
    - `"macos"`
        
    - `"windows"`
        
    - `"web"`
        
- Great for **one-off style differences**.
    
- Platform does **not change at runtime**, unlike dimensions.
    

---

### 2️⃣ Using `Platform.select()`

Alternative, more readable syntax:

```js
borderWidth: Platform.select({
  ios: 0,
  android: 2
})
```

✅ Returns the value for the current platform.  
✅ Useful when you have multiple platform-specific values.

---

### 3️⃣ Platform-Specific Files

React Native also allows creating files for a **specific platform**:

```
Title.js         // Default fallback
Title.ios.js     // Only for iOS
Title.android.js // Only for Android
```

- No need to change imports:
    

```js
import Title from "./components/Title"; // RN picks correct file
```

- Works with:
    
    - Components
        
    - Styles
        
    - Config / colors files
        
    - Any JS module
        
- Example for color palettes:
    

```
colors.ios.js
colors.android.js
```

```js
import colors from "../constants/colors"; // automatically uses correct platform
```

---

### 4️⃣ Use Cases

- Minor style tweaks (borders, font sizes)
    
- Platform-specific behavior (animations, touch feedback)
    
- Different color themes
    
- Components that only make sense on iOS or Android
    

---

### 5️⃣ Key Notes

- For **small differences**, `Platform.OS` or `Platform.select()` is enough.
    
- For **larger differences**, like totally different layout logic, use **platform-specific files**.
    
- Avoid putting platform suffixes in imports; React Native picks them automatically.
    

---

### 🔑 Summary

1. **Dynamic platform detection** → Platform.OS
    
2. **Readable conditional values** → Platform.select
    
3. **Platform-specific files** → `Component.ios.js`, `Component.android.js`
    
4. **Flexible** → Can be used for components, styles, constants, or any code
    

> With these tools, you can maintain one codebase while **tailoring UI and behavior** for each platform.
