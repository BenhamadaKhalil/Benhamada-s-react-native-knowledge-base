
# 📱 React Native – Screen Orientation (Introduction)

## 🚀 Main Idea
So far, we handled **different screen sizes** ✅  
Now we move to **screen orientation** 🔄

👉 Portrait vs Landscape can break your UI if not handled properly

---

## 🧠 Key Concepts

### 1. 🔒 Default Orientation (Expo)

By default, apps are often **locked to portrait mode**

📄 In `app.json`:
```json
{
  "expo": {
    "orientation": "portrait"
  }
}
````

---

### 2. 🔓 Unlocking Orientation

To allow rotation:

```json
{
  "expo": {
    "orientation": "default"
  }
}
```

Other options:

- `"portrait"` → only vertical
    
- `"landscape"` → only horizontal
    
- `"default"` → both allowed ✅
    

---

### 3. ⚠️ Important: Reload Required

After changing orientation settings:

- You must **restart / reload the app**
    

---

### 4. 📱 Device Rotation Behavior

- iOS → usually works automatically
    
- Android → may require:
    
    - enabling **auto-rotate** in emulator/device
        

---

## ⚛️ Real Problem Observed

When rotating the app:

### ❌ UI Issues

- Layout becomes **ugly or broken**
    
- Too much spacing
    
- Components not repositioned
    

### ❌ Usability Issues

- Keyboard overlaps input
    
- Cannot interact properly
    
- App becomes partially unusable
    

---

## 💡 Key Insight

> Supporting rotation is not just enabling it —  
> you must **adapt your UI for it**

---

## 🔥 Why This Matters

Different orientations mean:

- Different **available width/height**
    
- Different **layout needs**
    

👉 Portrait ≠ Landscape UI

---

## 🧩 What’s Missing Right Now

Even with:

- `Dimensions API` ✅
    
- Responsive widths ✅
    

We still **don’t react to orientation changes dynamically**

---

## 📌 Summary

- Apps can be locked or unlocked for rotation
    
- Controlled via `app.json` in Expo
    
- Rotation may break UI if not handled
    
- Landscape mode introduces new layout challenges
    
- Next step → make UI adapt to orientation
