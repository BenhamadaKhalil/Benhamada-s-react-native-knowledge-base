# 📱 React Native - Logging Guess Rounds & Rendering Lists

## 🧠 Core Idea

In this part, we:

- Track **all guesses (rounds)** in the GameScreen
    
- Store them in an **array state**
    
- Dynamically **render a list of guesses**
    
- Learn when to use `.map()` vs `FlatList`
    

---

## ⚙️ Key Concepts

### 1. Storing Multiple Values in State (Array State)

We store all guessed numbers in an array:

```js
const [guessRounds, setGuessRounds] = useState([initialGuess]);
```

👉 Why an array?

- Because we have **multiple rounds**
    
- Each round = one guessed number
    

👉 Initial value:

- Starts with `initialGuess` (first guess already exists)
    

---

### 2. Updating State Based on Previous State

When generating a new guess:

```js
setGuessRounds((prevGuessRounds) => {
  return [newRndNumber, ...prevGuessRounds];
});
```

### Important ideas:

- Use **function form** of `setState`
    
- Always rely on **previous state safely**
    
- Use **spread operator (`...`)** to keep old data
    

👉 This adds the newest guess **at the beginning**

---

### 3. Why Add at the Beginning?

```js
[newRndNumber, ...prevGuessRounds]
```

Instead of:

```js
[...prevGuessRounds, newRndNumber]
```

👉 Reason:

- Latest guess appears **on top of the list**
    
- Better UX for logs
    

---

### 4. Rendering a List with `.map()`

Basic approach:

```js
guessRounds.map((guessRound) => (
  <Text key={guessRound}>{guessRound}</Text>
));
```

👉 Each item:

- Is converted into a `<Text>` component
    
- Needs a **unique `key`**
    

---

### 5. Importance of Keys

```js
key={guessRound}
```

👉 Why this works:

- Each guessed number is **unique**
    
- Game logic prevents duplicates
    

👉 Rule:

- Keys must be:
    
    - Unique
        
    - Stable
        

---

### 6. Common Bug (Important)

❌ Wrong:

```js
return [...prevGuessRounds, prevGuessRounds];
```

✅ Correct:

```js
return [newRndNumber, ...prevGuessRounds];
```

👉 Mistake:

- Accidentally adding the entire array instead of the new value
    

👉 Result:

- Broken or weird UI output
    

---

## 🔄 `.map()` vs `FlatList`

### Using `.map()`:

✔ Simple  
✔ Good for small lists  
❌ Not optimized for large lists

---

### Using `FlatList` (Recommended for larger data):

```js
import { FlatList } from 'react-native';
```

👉 Benefits:

- Better performance
    
- Lazy loading (renders only visible items)
    
- Built-in optimizations
    

---

### When to Use Which?

|Situation|Use|
|---|---|
|Small list (5–10 items)|`.map()` ✅|
|Large / dynamic list|`FlatList` 🚀|

👉 In this app:

- `.map()` is technically fine
    
- But `FlatList` is used for **best practice**
    

---

## 💡 Practical Notes

- Always use **functional updates** when state depends on previous state
    
- Think about **UI order** (latest first vs last)
    
- Keys are critical — bad keys = bugs
    
- `FlatList` is standard in real apps
    

---

## 📌 Summary

- Guess history is stored in an **array state**
    
- New guesses are added using:
    
    - functional updates
        
    - spread operator
        
- Lists can be rendered with:
    
    - `.map()` (simple)
        
    - `FlatList` (optimized)
        
- Correct key usage is essential for stable UI
