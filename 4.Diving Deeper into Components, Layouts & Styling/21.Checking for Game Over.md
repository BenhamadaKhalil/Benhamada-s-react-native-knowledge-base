## 1️⃣ Detecting Game Over

- The game ends **when the device correctly guesses the user’s number**.
    
- We need to compare `currentGuess` (state) with `userNumber` (prop) whenever `currentGuess` changes.
    
- **React way:** use the `useEffect` hook.
    

```ts
useEffect(() => {
  if (currentGuess === userNumber) {
    onGameOver(); // Call function passed from App.js
  }
}, [currentGuess, userNumber, onGameOver]);
```

- Dependencies: `currentGuess`, `userNumber`, `onGameOver`  
    → ensures effect runs **exactly when guess changes**.
    

---

## 2️⃣ Communicating with App.js

- In `App.js`, manage a **game over state**:
    

```ts
const [gameIsOver, setGameIsOver] = useState(true); // initially true
```

- Define a handler to trigger game over:
    

```ts
function gameOverHandler() {
  setGameIsOver(true);
}
```

- Pass this to `GameScreen`:
    

```tsx
<GameScreen 
  userNumber={userNumber} 
  onGameOver={gameOverHandler} 
/>
```

- In `GameScreen`, we call `onGameOver()` from `useEffect` when the guess matches.

## 3️⃣ Avoiding Starting in “Game Over” state

- When a number is picked:
    

```ts
function startGameHandler(pickedNumber) {
  setUserNumber(pickedNumber);
  setGameIsOver(false); // Reset state
}
```

- This ensures the game starts fresh and doesn’t immediately render the GameOverScreen.

## 4️⃣ Fixing the Infinite Loop

- **Why it happened:**
    
    - The initial guess is generated every time the GameScreen renders:
        
    
    ```ts
    const [currentGuess, setCurrentGuess] = useState(
      generateRandomBetween(minBoundary, maxBoundary, userNumber)
    );
    ```
    
    - When `minBoundary === maxBoundary` (final number), `generateRandomBetween` enters recursion trying to exclude the previous guess → **stack overflow**.
        
- **Solution:**
    
    - Hard-code initial min/max for the first guess only.
        
    - After the first guess, only `nextGuessHandler` updates the guess.
        
    - `useEffect` handles the transition to GameOver before the next render can recurse.
        

```ts
// Only used for initial guess
const initialGuess = generateRandomBetween(1, 100, userNumber);
const [currentGuess, setCurrentGuess] = useState(initialGuess);
```

- This ensures the infinite loop **cannot happen** after the correct number is reached.

## 5️⃣ Summary Flow

1. **Start Screen:** user picks a number → `startGameHandler()` sets `userNumber` & `gameIsOver = false`.
    
2. **Game Screen:**
    
    - initial guess generated
        
    - displayed in `NumberContainer`
        
3. **User feedback:**
    
    - `+` or `-` updates boundaries in `nextGuessHandler()`
        
    - new guess generated and `currentGuess` updated
        
4. **Check for game over:** `useEffect` compares `currentGuess` to `userNumber`
    
    - If equal → call `onGameOver()` → App.js sets `gameIsOver = true`
        
5. **Render GameOverScreen** instead of GameScreen

✅ **Key learning points:**

- `useEffect` runs **after render**, so initial render may still run logic with outdated state → careful with initial boundaries.
    
- Always **reset game state** when starting a new game.
    
- **Validate user hints** to prevent impossible ranges and infinite loops.
    
- Separation of responsibilities: `App.js` controls which screen renders, `GameScreen` controls game logic, `NumberContainer` handles display.
