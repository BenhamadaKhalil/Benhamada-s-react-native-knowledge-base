
# 📱 React Native – Configuring TextInput (Keyboard & Behavior)

## 🧠 Core Idea
Beyond styling, `TextInput` can be **configured** to control:
- Which keyboard appears
- How text behaves (auto-capitalization, auto-correct)

👉 This greatly improves **user experience (UX)**

---

## ⌨️ Controlling the Keyboard Type

### Problem:
- Default keyboard shows **all characters**
- Not مناسب for numeric input ❌

---

### ✅ Solution: `keyboardType`

```tsx
<TextInput keyboardType="number-pad" />
````

👉 Opens a keyboard with:

- Only numbers
    
- Faster input
    
- Better UX
    

---

## 🔑 Common `keyboardType` Values

|Value|Description|Platform|
|---|---|---|
|`default`|Normal keyboard|Both|
|`number-pad`|Numbers only|Both ✅|
|`decimal-pad`|Numbers + decimal|iOS only|
|`email-address`|Optimized for emails|Both|
|`url`|URL keyboard|iOS only|

👉 Always check compatibility in docs

---

## 🔠 Auto Capitalization

```tsx
<TextInput autoCapitalize="none" />
```

### Options:

- `none` → no capitalization ✅
    
- `sentences` → first letter of sentence
    
- `words` → every word
    
- `characters` → ALL CAPS
    

👉 Useful for:

- Emails
    
- Usernames
    
- Passwords
    

---

## ✍️ Auto Correct

```tsx
<TextInput autoCorrect={false} />
```

👉 Prevents annoying behavior like:

- Wrong corrections
    
- Changing user input unexpectedly
    

---

## 🧩 Final Input Configuration

```tsx
<TextInput
  style={styles.numberInput}
  maxLength={2}
  keyboardType="number-pad"
  autoCapitalize="none"
  autoCorrect={false}
/>
```

---

## ⚠️ Important Notes

- `keyboardType="number-pad"`:
    
    - Improves UX ✅
        
    - BUT does NOT fully prevent invalid input ❌
        

👉 Users can still paste invalid values

---

## 💡 Best Practice

Always combine:

1. UI restriction (keyboardType)
    
2. Input limit (maxLength)
    
3. Validation logic (later)
