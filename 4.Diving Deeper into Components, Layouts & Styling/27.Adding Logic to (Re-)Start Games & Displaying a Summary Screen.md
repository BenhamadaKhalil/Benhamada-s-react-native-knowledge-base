# 📱 React Native - Game Over Screen & State Reset

## 🧠 Core Idea

This part focuses on:

- Passing **game results data** (rounds + user number) to the **GameOverScreen**
    
- Handling **game restart logic**
    
- Resetting game-related state properly
    
- Using `useEffect` to reset values when a component is mounted
    

---

## ⚙️ Key Concepts

### 1. Passing Data via Props

The `GameOverScreen` should not manage its own data. Instead, it **receives data from the App component**.

Props passed:

- `roundsNumber` → number of rounds taken
    
- `userNumber` → the number chosen by the user
    
- `onStartNewGame` → function to restart the game
    

```js
function GameOverScreen({ roundsNumber, userNumber, onStartNewGame }) {
```

👉 This uses **object destructuring** to directly extract props.

---

### 2. Displaying Dynamic Values

You replace placeholders with actual data:

- X → `roundsNumber`
    
- Y → `userNumber`
    

```js
<Text>Number of rounds: {roundsNumber}</Text>
<Text>Number was: {userNumber}</Text>
```

---

### 3. Handling Button Actions

The "New Game" button triggers a function passed from the parent:

```js
<Button title="New Game" onPress={onStartNewGame} />
```

👉 Important idea:

- You pass a **function reference**, not execute it immediately.
    

---

### 4. Managing State in App Component

#### Add new state for rounds:

```js
const [guessRounds, setGuessRounds] = useState(0);
```

- Initially `0` because the game hasn’t started.
    

#### Pass data to GameOverScreen:

```js
<GameOverScreen
  userNumber={userNumber}
  roundsNumber={guessRounds}
  onStartNewGame={startNewGameHandler}
/>
```

---

### 5. Restart Game Logic

Create a handler function:

```js
function startNewGameHandler() {
  setUserNumber(null);
  setGuessRounds(0);
}
```

#### What happens here:

- `userNumber = null` → returns to start screen
    
- `guessRounds = 0` → reset progress
    

👉 Smart trick:

- Since `userNumber` becomes `null`, conditional rendering automatically switches screens.
    

---

## 🔄 Screen Switching Logic (Important)

React Native UI depends on conditions like:

```js
if (!userNumber) {
  return <StartGameScreen />;
}
```

👉 Resetting state = automatic navigation between screens

## 🧩 Resetting Variables Outside Components

### Problem:

Some values (like `minBoundary` and `maxBoundary`) are:

- Defined **outside** the component
    
- Not reset automatically
    

### Solution: `useEffect`

```js
useEffect(() => {
  minBoundary = 1;
  maxBoundary = 100;
}, []);
```

### Why this works:

- Runs **only once when component mounts**
    
- Runs again if component is removed and re-added
    

👉 Perfect for resetting game limits when a new game starts

---

## ⚠️ Important Behavior of `useEffect`

- `[]` dependency → runs only on first render
    
- Does NOT run on every re-render
    
- Runs again only if component is unmounted and mounted again
    

---

## 💡 Practical Notes

- Always **lift state up** (App manages data, child displays it)
    
- Use **function props** to let child components trigger parent logic
    
- Resetting state can control **navigation flow**
    
- Variables outside components need **manual reset**
