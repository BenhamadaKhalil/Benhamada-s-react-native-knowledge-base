# ⭐ App-Wide State & Favorites Feature

## 🧠 Core Idea
In real-world apps, some data (state) must be **shared across multiple screens**.

👉 Example in this app:
- You mark a meal as a **favorite** on the Meal Detail screen
- That same meal must appear on the **Favorites screen**

➡️ This means the "favorite status" must be **globally accessible (app-wide state)**

---

## ⚙️ Key Concepts

### 📌 1. Local vs App-Wide State
- **Local State** (useState):
  - Only available inside one component/screen
  - ❌ Not suitable for multi-screen data

- **App-Wide State**:
  - Shared across multiple screens/components
  - ✅ Needed for features like favorites, auth, cart, etc.

---

### 📌 2. The Problem We’re Solving
We need to:
1. Tap ⭐ on Meal Detail screen → mark as favorite
2. Store that information somewhere globally
3. Access it in:
   - Meal Detail screen (to toggle icon)
   - Favorites screen (to display meals)

➡️ This requires **centralized state management**

---

### 📌 3. Solutions for App-Wide State

#### 🟢 React Context API
- Built into React
- Good for **medium-sized apps**
- Avoids prop drilling

#### 🔵 Redux
- External library
- More powerful & structured
- Better for **large/complex apps**

---

## 🧩 Example Flow (Favorites Feature)

```text
[Meal Detail Screen]
        ↓ (toggle favorite)
   Update global state
        ↓
[Global Store / Context]
        ↓
[Favorites Screen reads data]
        ↓
Display favorite meals
````

---

## 💡 Notes & Tips

- 🔁 This is a **very common pattern** in apps:
    
    - Favorites
        
    - Shopping cart
        
    - User authentication
        
    - Theme (dark/light mode)
        
- ⚠️ You CANNOT rely on:
    
    - Passing props between screens
        
    - Local state
        
- 🧠 Think of global state as a **single source of truth**
