
# 🌍 Setting Up App-Wide State with Context API

## 🧠 Core Idea
We start implementing **global state management** using the **React Context API**.

👉 Goal:
Create a **central place (context)** to manage favorite meals across the entire app.

---

## ⚙️ Key Concepts

### 📌 1. Folder Structure for State Management
A common convention is to create a **store folder**:

```

/store  
/context  
/redux

```

- `context/` → for Context API logic
- `redux/` → for Redux (later)

➡️ This keeps state logic **organized and scalable**

---

### 📌 2. Creating a Context

In:
```

store/context/favorites-context.js

````

We create a context using `createContext`:

```js
import { createContext } from 'react';

export const FavoritesContext = createContext({
  ids: [],
  addFavorite: (id) => {},
  removeFavorite: (id) => {},
});
````

#### 🧠 Why this structure?

- `ids` → stores favorite meal IDs
    
- `addFavorite` → add new favorite
    
- `removeFavorite` → remove favorite
    

⚠️ These are **dummy functions**  
→ Only added for:

- IDE auto-completion
    
- Better developer experience
    

---

### 📌 3. Creating the Provider Component

```js
export default function FavoritesContextProvider({ children }) {
  return (
    <FavoritesContext.Provider value={{}}>
      {children}
    </FavoritesContext.Provider>
  );
}
```

#### 🧠 Key Idea:

- This component **wraps your app**
    
- Makes context available to all child components
    

---

### 📌 4. Why Use a Provider?

👉 Without Provider:

- Context is **not accessible**
    

👉 With Provider:

- Any component inside can:
    
    - Read state
        
    - Update state
        

---

## 🧩 Wrapping the App

In `App.js`:

```js
import FavoritesContextProvider from './store/context/favorites-context';

export default function App() {
  return (
    <FavoritesContextProvider>
      <NavigationContainer>
        {/* all screens */}
      </NavigationContainer>
    </FavoritesContextProvider>
  );
}
```

---

### 🧠 Why wrap around Navigation?

Because we need access in:

- Meal Detail Screen ⭐
    
- Favorites Screen ❤️
    
- Any other screen later
    

➡️ Wrapping the entire navigation ensures **global access**

---

## 💡 Notes & Tips

- 📛 Naming convention:
    
    - Context → `FavoritesContext`
        
    - Provider → `FavoritesContextProvider`
        
- 🔠 Capitalization matters:
    
    - Components must start with uppercase
        
- 🧠 Think of Provider as:
    
    > A "global wrapper" that injects shared data into your app
    
- ⚠️ At this stage:
    
    - Context is just a **shell**
        
    - No real logic yet → will cause errors
