# ✏️ 1. Updating an Expense (PUT)

## ⚙️ Function: updateExpense

In `http.js`:

```js id="upd1"
import axios from "axios";

const BACKEND_URL = "https://your-project-id.firebaseio.com/";

export function updateExpense(id, expenseData) {
  return axios.put(
    `${BACKEND_URL}expenses/${id}.json`,
    expenseData
  );
}
````

---

## 🔥 Key Idea

Firebase structure:

```
/expenses/{id}.json
```

So:

- ID is part of the URL
    
- That’s how Firebase identifies the item
    

---

## 📦 What we send

We ONLY send:

```js
{
  amount,
  date,
  description
}
```

❌ NOT:

- id (already in URL)
    

---

## ⚡ Why PUT?

- Replaces full object at that ID
    
- Ensures backend matches frontend
    

---

# 🗑️ 2. Deleting an Expense (DELETE)

## ⚙️ Function: deleteExpense

```js
export function deleteExpense(id) {
  return axios.delete(`${BACKEND_URL}expenses/${id}.json`);
}
```

---

## 💡 Key Idea

- Same URL pattern as update
    
- No request body needed
    

---

# 📲 Using in ManageExpense

## ✏️ Update Flow

### 1. Update locally first (optimistic update)

```js
expensesCtx.updateExpense(id, expenseData);
```

---

### 2. Then sync with backend

```js
await updateExpense(id, expenseData);
```

---

## 💡 Why local first?

This is called:

### ⚡ Optimistic UI Update

- UI updates instantly
    
- Backend sync happens after
    

✔ Better user experience  
✔ No waiting delay

---

# 🗑️ Delete Flow

```js
await deleteExpense(id);
expensesCtx.deleteExpense(id);
```

(or reversed depending on preference)

---

# 🔄 Full Flow Summary

## ✏️ Update Expense

1. User edits expense
    
2. App updates local context
    
3. App sends PUT request to Firebase
    
4. Firebase replaces data at `/expenses/{id}`
    

---

## 🗑️ Delete Expense

1. User clicks delete
    
2. App removes from context
    
3. App sends DELETE request to Firebase
    
4. Firebase removes item completely
    

---

# ⚠️ Notes / Pitfalls

- Always use **Firebase ID in URL**
    
- Never include ID inside request body
    
- PUT replaces full object (not partial merge)
    
- DELETE requires only ID
    
- Optimistic updates improve UX but require error handling later

    - `/expenses.json` → collection
        
    - `/expenses/{id}.json` → single item

- DELETE = remove object
