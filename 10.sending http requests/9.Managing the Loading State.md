# ⏳ Adding Loading Feedback (LoadingOverlay in React Native)

## 🧩 Concept
To improve user experience, we show a **loading spinner** while:

- 📥 Fetching expenses
- ➕ Adding an expense
- ✏️ Updating an expense
- 🗑️ Deleting an expense

Instead of showing empty or outdated UI, we display a **LoadingOverlay**.

---

# 🧱 1. Creating LoadingOverlay Component

📁 `ui/LoadingOverlay.js`

```js id="ov1"
import { View, ActivityIndicator, StyleSheet } from "react-native";
import { GlobalStyles } from "../constants/styles";

function LoadingOverlay() {
  return (
    <View style={styles.container}>
      <ActivityIndicator size="large" color="white" />
    </View>
  );
}

export default LoadingOverlay;
````

---

## 🎨 Styling the Overlay

```js
const styles = StyleSheet.create({
  container: {
    flex: 1,
    justifyContent: "center",
    alignItems: "center",
    padding: 24,
    backgroundColor: GlobalStyles.colors.primary700,
  },
});
```

---

## 💡 Key Component Used

### `ActivityIndicator`

- Built-in React Native spinner
    
- Automatically adapts to platform (Android / iOS)
    
- Configurable via:
    
    - `size`
        
    - `color`

# 📥 2. Loading State in RecentExpenses

## ⚙️ Add State

```js
const [isFetching, setIsFetching] = useState(true);
```

---

## 🔄 Fetch Logic

```js
useEffect(() => {
  async function getExpenses() {
    setIsFetching(true);

    const expenses = await fetchExpenses();
    expensesCtx.setExpenses(expenses);

    setIsFetching(false);
  }

  getExpenses();
}, []);
```

---

## 🧠 Conditional UI Rendering

```js
if (isFetching) {
  return <LoadingOverlay />;
}
```

---

## 💡 Result

- App shows spinner immediately on load
    
- No more "empty state flicker"
    
- Data appears only after loading completes

# ⚙️ 3. Loading State in ManageExpense

```js
const [isSubmitting, setIsSubmitting] = useState(false);
```

---

# 🗑️ Delete Flow

```js
async function deleteExpenseHandler() {
  setIsSubmitting(true);

  await deleteExpense(expenseId);
  expensesCtx.deleteExpense(expenseId);

  navigation.goBack();
}
```

---

# ✏️ Add / Update Flow

```js
async function confirmHandler(expenseData) {
  setIsSubmitting(true);

  if (isEditing) {
    await updateExpense(expenseId, expenseData);
    expensesCtx.updateExpense(expenseId, expenseData);
  } else {
    const id = await storeExpense(expenseData);
    expensesCtx.addExpense({ ...expenseData, id });
  }

  navigation.goBack();
}
```

---

## 🧠 Conditional UI

```js
if (isSubmitting) {
  return <LoadingOverlay />;
}
```

# 🔄 Full UX Flow

## 📥 Fetching

1. Screen loads
    
2. Spinner appears
    
3. Data fetched
    
4. Spinner disappears
    
5. Expenses shown
    

---

## ➕ Adding / ✏️ Updating / 🗑️ Deleting

1. User action triggered
    
2. Spinner appears immediately
    
3. Request sent to Firebase
    
4. Context updated
    
5. Screen closes
    
6. Spinner disappears automatically
    

---

# ⚠️ Notes / Pitfalls

- Always reset loading state after async operations (if screen stays open)
    
- Avoid showing both UI and spinner at same time (use early return)
    
- `ActivityIndicator` is lightweight → prefer it over custom loaders
    
- Navigation back can replace manual state reset in some cases
    

---

# 🔑 Key Takeaways

- React Native uses `ActivityIndicator` for loading UI
    
- Loading state improves UX by avoiding “blank flashes”
    
- Two important states:
    
    - `isFetching` → loading data
        
    - `isSubmitting` → sending data
        
- Use **conditional rendering (early return)** for loaders
    
- Works the same as React, but with native UI components
