# 🔄 Syncing Backend Data with Context (Final Architecture Fix)

## 🧩 Concept
After fetching expenses from Firebase, we initially tried to:
- Store them in **local state inside `RecentExpenses`**
- Then render UI from that state

This worked, but created a **data synchronization problem**.

---

## ❌ Problem with Local State in Screen

Using:

- `useState` in `RecentExpenses`
- Fetching data only on first render (`useEffect`)

### Issue:
Because of React Navigation **Stack behavior**:
- Screens are NOT destroyed when navigating away
- They stay in memory (background)

👉 Result:
- `useEffect` runs only once
- New expenses don’t appear automatically
- App must be reloaded manually

---

## 🧠 Why This Happens

With Stack Navigator:
- `RecentExpenses` stays mounted
- `useEffect` does NOT re-run on navigation
- So data is NOT refetched

---

## 💡 Better Solution: Use Context as Single Source of Truth

Instead of managing fetched data in a screen:

👉 We move everything into **Expenses Context**

This gives us:
- Shared state across app
- Automatic updates everywhere
- No duplicate logic in screens

---

## 🏗️ Updating Context Structure

### 1. Remove dummy data
Context state starts empty:

```js id="ctx1"
const [expenses, setExpenses] = useState([]);
````

---

### 2. Add SET action in reducer

```js
case "SET":
  return action.payload;
```

---

### 3. Add setExpenses function

```js
function setExpenses(expenses) {
  dispatch({ type: "SET", payload: expenses });
}
```

---

### 4. Expose it via context

```js
value={{
  expenses,
  addExpense,
  setExpenses,
  deleteExpense,
  updateExpense,
}}
```

---

## 📥 Using Fetched Data Correctly

Inside `RecentExpenses`:

### ❌ Old approach (removed)

- Local state (`useState`)
    
- Manual syncing
    

---

### ✅ New approach

```js
const expensesCtx = useContext(ExpensesContext);
```

Then after fetching:

```js
useEffect(() => {
  async function getExpenses() {
    const expenses = await fetchExpenses();
    expensesCtx.setExpenses(expenses);
  }

  getExpenses();
}, []);
```

---

## 📲 Rendering UI

Now everything comes from context:

```js
const recentExpenses = expensesCtx.expenses.filter((expense) => {
  const today = new Date();
  const date7DaysAgo = new Date(today.setDate(today.getDate() - 7));

  return expense.date >= date7DaysAgo;
});
```

---

## ➕ Adding New Expense (Important Improvement)

When adding an expense:

- We already have data locally
    
- So we update context immediately
    
- AND send request to backend
    

👉 No need to refetch everything again

---

## ⚙️ Final Flow

### ➕ Add Expense

1. Add locally (context)
    
2. Send POST to Firebase
    

### 📥 Fetch Expenses

1. Load from Firebase
    
2. Store in context
    

### 📲 Display UI

- Always read from context
    

---

## 🚀 Why This Architecture is Better

### Before ❌

- Local screen state
    
- Manual syncing
    
- Navigation bugs
    
- Missing updates
    

### After ✅

- Centralized state (Context)
    
- Single source of truth
    
- Instant UI updates
    
- Fewer HTTP requests
    
- Cleaner architecture
    

---

## ⚠️ Notes / Pitfalls

- Never duplicate backend data in screen state
    
- Stack Navigator keeps screens alive → don’t rely on remounting
    
- Context should be the **main data layer**
    
- HTTP layer = backend sync only, not UI storage
    

---

## 🔑 Key Takeaways

- React Navigation keeps screens mounted in background
    
- Local `useState` is not enough for shared data
    
- Context = **single source of truth**
    
- Fetch once → store globally → reuse everywhere
    
- This reduces network requests and improves UX
