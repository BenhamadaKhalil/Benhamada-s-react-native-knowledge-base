# 🌐 Connecting React Native App to a Backend (HTTP Requests)

## 🧩 Concept
In this section, the app moves from being **offline-only** to interacting with a **backend server**.

A backend typically includes:
- A **database** (to store data)
- A **server** (where logic runs)
- An **API** (to communicate with the app)

Instead of storing everything on the device, the app will:
- Send data to a server
- Fetch data from a server
- Update and delete data remotely

---

## ⚙️ Backend & API Basics

- Mobile apps **don’t need HTML responses** (unlike websites)
- They communicate with a backend through an **API**
- Most commonly, this is a **REST API**

👉 The API is responsible for:
- Receiving requests (from the app)
- Processing data
- Sending back responses (usually JSON)

---

## 🔥 Why Firebase is Used

In this course:

💡 Important:
> The concepts you learn here apply to **any backend**
- Node.js (Express)
- Django
- PHP
- .NET

---

## 🔄 HTTP Requests (Core Actions)

The app will learn to perform:

- **GET** → Fetch data  
- **POST** → Store new data  
- **PUT / PATCH** → Update existing data  
- **DELETE** → Remove data  

These are sent as **HTTP requests** to the API.

---

## ⏳ Handling Request States

When working with APIs, you must manage UI states:

### 1. Loading State
- While waiting for a response
- Example: show a spinner

### 2. Error State
- If request fails (network/server issue)
- Show error message to user

### 3. Success State
- Data received or updated successfully
- Update UI accordingly

---

## 💻 Example Flow

```js
// Example of fetching data
useEffect(() => {
  setIsLoading(true);

  fetch("https://example.com/data")
    .then((response) => response.json())
    .then((data) => {
      setData(data);
    })
    .catch((error) => {
      setError(error);
    })
    .finally(() => {
      setIsLoading(false);
    });
}, []);
````

---

## ⚠️ Notes / Pitfalls

- Don’t assume requests are instant → always handle loading
    
- Always handle errors (network can fail anytime)
    
- Keep backend logic separate from UI logic
    
- API must return **data (JSON)**, not HTML
    

---

## 🔑 Key Takeaways

- Mobile apps rely on **APIs** to communicate with backends
    
- **Firebase** is used here as a simple backend
    
- The same logic applies to **any backend technology**
    
- HTTP requests allow full data control (CRUD)
    
- Managing **loading & error states** is essential for good UX
