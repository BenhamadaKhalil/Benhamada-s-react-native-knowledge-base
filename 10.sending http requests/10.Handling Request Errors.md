# ❌ Handling Errors in HTTP Requests (ErrorOverlay + try/catch)

## 🧩 Concept
Now we handle what happens when **HTTP requests fail**.

Failures can happen because of:
- 🌐 No internet connection
- 🔥 Firebase/server issues
- ❌ Wrong URL or bad request
- ⏳ Timeout or network errors

👉 Without handling errors:
- App freezes (loading forever ❌)
- User sees nothing
- Promise warnings appear

---

# 🧱 1. Creating ErrorOverlay Component

📁 `ui/ErrorOverlay.js`

```js id="err1"
import { View, Text, StyleSheet } from "react-native";
import Button from "./Button";
import { GlobalStyles } from "../constants/styles";

function ErrorOverlay({ message, onConfirm }) {
  return (
    <View style={styles.container}>
      <Text style={[styles.textBase, styles.title]}>
        An error occurred!
      </Text>

      <Text style={styles.textBase}>
        {message}
      </Text>

      <Button onPress={onConfirm}>Okay</Button>
    </View>
  );
}

export default ErrorOverlay;
````

# ⚙️ 2. Error State in RecentExpenses

## 📌 Add State

```js
const [error, setError] = useState();
const [isFetching, setIsFetching] = useState(true);
```

---

## 🔄 Fetch with try/catch

```js
useEffect(() => {
  async function getExpenses() {
    setIsFetching(true);

    try {
      const expenses = await fetchExpenses();
      expensesCtx.setExpenses(expenses);
    } catch (error) {
      setError("Could not fetch expenses!");
    }

    setIsFetching(false);
  }

  getExpenses();
}, []);
```

---

## 🚨 Show Error UI

```js
if (error && !isFetching) {
  return <ErrorOverlay message={error} />;
}
```

# 🗑️ 3. Error Handling in ManageExpense

## 📌 Add State

```js
const [error, setError] = useState();
const [isSubmitting, setIsSubmitting] = useState(false);
```

---

## ❌ Delete with error handling

```js
async function deleteExpenseHandler() {
  setIsSubmitting(true);

  try {
    await deleteExpense(expenseId);
    expensesCtx.deleteExpense(expenseId);
    navigation.goBack();
  } catch (error) {
    setError("Could not delete expense!");
    setIsSubmitting(false);
  }
}
```

---

## ✏️ Add / Update with error handling

```js
async function confirmHandler(expenseData) {
  setIsSubmitting(true);

  try {
    if (isEditing) {
      await updateExpense(expenseId, expenseData);
      expensesCtx.updateExpense(expenseId, expenseData);
    } else {
      const id = await storeExpense(expenseData);
      expensesCtx.addExpense({ ...expenseData, id });
    }

    navigation.goBack();
  } catch (error) {
    setError("Could not save data!");
    setIsSubmitting(false);
  }
}
```

---

## 🚨 Show Error Overlay

```js
if (error && !isSubmitting) {
  return <ErrorOverlay message={error} />;
}
```

# ⚠️ Important Concepts

## 🧠 try/catch with async

- `try` → run request
    
- `catch` → handle failure
    

---

## 🔄 State Separation

We now have 2 UI states:

### ⏳ Loading

- `isFetching`
    
- `isSubmitting`
    

### ❌ Error

- `error`
    

👉 These should NEVER overlap incorrectly.

---

## 💡 Why this matters

Without error handling:

- App freezes on failure ❌
    
- User thinks app is broken
    

With error handling:

- Clear feedback ✔
    
- Better UX ✔
    
- More professional app ✔
    

---

# 🔑 Key Takeaways

- Always wrap HTTP calls in `try/catch`
    
- Show **ErrorOverlay** when something fails
    
- Stop loading state in `catch`
    
- Use separate state for:
    
    - loading (`isFetching`, `isSubmitting`)
        
    - errors (`error`)
        
- Never leave user stuck on infinite spinner
