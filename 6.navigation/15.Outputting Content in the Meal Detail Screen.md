---

## 📦 2. Getting the selected meal data

We retrieve the full meal using the `mealId` from route params.

```js
import { MEALS } from '../data/dummy-data';

const selectedMeal = MEALS.find(
  (meal) => meal.id === mealId
);
```

### 💡 Key idea

- `mealId` comes from navigation params
    
- `.find()` returns the full meal object
    

---

## 🖼️ 3. Displaying the meal image

For network images, React Native requires `uri` + dimensions.

```js
import { Image } from 'react-native';

<Image
  source={{ uri: selectedMeal.imageUrl }}
/>
```

### ⚠️ Important

- Network images MUST have width + height (we fix styling later)
    
- Otherwise image won’t render

## ♻️ 5. Creating a reusable component: MealDetails

### 🎯 Why?

We reuse the same UI in:

- MealItem (list screen)
    
- MealDetailScreen
    

---

### 📦 MealDetails component

```js
function MealDetails({ duration, complexity, affordability }) {
  return (
    <View>
      <Text>{duration}m</Text>
      <Text>{complexity}</Text>
      <Text>{affordability}</Text>
    </View>
  );
}

export default MealDetails;
```

---

## 🍽️ 9. Rendering ingredients (manual list)

Since ingredients are short, we use `.map()` instead of FlatList.

```js
{selectedMeal.ingredients.map((ingredient) => (
  <Text key={ingredient}>{ingredient}</Text>
))}
```

### 💡 Why no FlatList?

- Small dataset (5–10 items)
    
- No performance need
    

---

## 👨‍🍳 10. Rendering steps

Same approach as ingredients:

```js
{selectedMeal.steps.map((step) => (
  <Text key={step}>{step}</Text>
))}
```

---

## ⚠️ 11. Important React Native rule (keys)

When using `.map()`:

- Always add a `key`
    
- Prefer unique values (strings here are fine)
