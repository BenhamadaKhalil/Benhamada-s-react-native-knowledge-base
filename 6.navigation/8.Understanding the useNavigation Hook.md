## 📌 Native Stack vs Stack + Navigation Access (React Navigation Deep Dive)

---

## 🧠 1. Native Stack vs Stack Navigator

React Navigation gives you two main stack options:

---

### 🚀 Native Stack (what we use)

```js
@react-navigation/native-stack
```

### 💡 Characteristics:

- Uses **real native platform navigation**
    
- iOS uses UIKit transitions
    
- Android uses native Android transitions
    
- Better **performance + smoother animations**
    

---

### ⚙️ Classic Stack

```js
@react-navigation/stack
```

### 💡 Characteristics:

- Navigation is **JS-based (emulated)**
    
- Works the same logically
    
- Slightly less performant
    
- More customizable in some edge cases
    

---

## ⚖️ Key Difference

|Feature|Native Stack|Stack|
|---|---|---|
|Performance|⭐ High|متوسط|
|Animations|Native (smooth)|JS-based|
|Behavior|Platform-native|Emulated|
|Recommendation|✅ Preferred|Fallback|

---

## 🧠 Conclusion

👉 Use **Native Stack by default**  
👉 Use **Stack only if you face compatibility issues**

---

## 🧭 2. How Navigation Works in Screens

When you register a screen:

```js
<Stack.Screen name="Categories" component={CategoriesScreen} />
```

React Navigation automatically injects:

```js
props.navigation
```

---

## ⚠️ Important Rule

👉 You only get `navigation` prop in:

- ✅ Screen components (registered in Stack.Screen)
    
- ❌ NOT in child components
    

---

## 🧩 3. Problem: Nested Components Can’t Access Navigation

Example:

```txt
CategoriesScreen
   └── CategoryGridTile ❌ no navigation prop
```

So inside `CategoryGridTile`:

- You don’t have access to `navigation`
    
- But you still may want to navigate
    

---

## 🔁 4. Solution 1 — Prop Drilling (Manual Forwarding)

### Step 1 (Screen → child):

```js
<CategoryGridTile onPress={pressHandler} />
```

### Step 2 (child uses it):

```js
<Pressable onPress={onPress}>
```

### ⚠️ Problem:

- Works but becomes messy in deep component trees
    
- Lots of forwarding props
    

---

## 🚀 5. Solution 2 — useNavigation Hook (BEST)

React Navigation provides:

```js
import { useNavigation } from "@react-navigation/native";
```

---

## 🧠 How it works

Inside ANY component:

```js
const navigation = useNavigation();
```

Now you can:

```js
navigation.navigate("MealsOverview");
```

---

## 💡 Why this is powerful

- Works in:
    
    - components
        
    - deeply nested UI
        
    - reusable components
        
- No prop drilling needed
    
- Clean architecture
    

---

## ⚠️ Important Note

```txt
useNavigation only works if the component is inside a NavigationContainer tree
```

---

## 🔄 Comparison

|Method|Pros|Cons|
|---|---|---|
|Props forwarding|explicit|messy in deep trees|
|useNavigation|clean + scalable|implicit dependency|

---

## 📱 Real Use Case in Your App

Instead of:

```js
props.onPress → CategoriesScreen → navigation.navigate
```

You can directly do:

```js
CategoryGridTile → useNavigation → navigate
```

---

## 📚 Quick Summary

- Native Stack = recommended (better performance + native feel)
    
- Stack = fallback option
    
- Navigation prop is only available in screen components
    
- Two ways to navigate from child components:
    
    1. Prop drilling (manual)
        
    2. `useNavigation()` hook (recommended)
        
- Hook avoids messy prop forwarding
    

---

## 🚀 Key Takeaway

👉 Prefer:

```js
useNavigation()
```

for reusable components  
👉 Use props only for simple cases
