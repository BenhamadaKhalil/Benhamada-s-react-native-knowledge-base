## 🧠 React Native Notes — Navigation to Meal Detail Screen (React Navigation)

### 🎯 Goal of this lesson

Create a **Meal Detail screen**, register it in navigation, navigate to it when a meal is pressed, and pass the **meal ID as a parameter**.

---

## 📱 1. Creating a new screen (Meal Detail)

We start by creating a new screen component:

- File: `MealDetailScreen.js`
    
- Simple placeholder content first
    

```js
import { Text } from 'react-native';

function MealDetailScreen() {
  return <Text>This is the meal detail screen</Text>;
}

export default MealDetailScreen;
```

### 💡 Key idea

At this stage, the screen is just a placeholder — real data will come later.

---

## 🧭 2. Registering the screen in the navigator

All screens are registered inside `App.js` using the stack navigator.

```js
<Stack.Screen
  name="MealDetail"
  component={MealDetailScreen}
/>
```

### 📌 Important notes:

- `name="MealDetail"` → this is the **navigation key**
    
- `component={MealDetailScreen}` → the screen to display
    
- Position in stack does NOT matter
    

---

## 🖱️ 3. Trigger navigation from a non-screen component

We want to navigate when a meal item is pressed.

But `MealItem` is NOT a screen → so it doesn’t receive `navigation` prop.

### Solution: use `useNavigation`

```js
import { useNavigation } from '@react-navigation/native';

const navigation = useNavigation();
```

---

## 🔁 4. Navigate to Meal Detail screen

Inside `MealItem`:

```js
navigation.navigate('MealDetail', {
  mealId: id,
});
```

### 📌 What happens here:

- `'MealDetail'` → screen name (must match App.js)
    
- `{ mealId: id }` → data passed to the screen
    

---

## ⚠️ 5. Important mistake (common bug)

Initially, navigation was triggered **immediately during render**, instead of on press.

❌ Wrong:

```js
onPress={navigation.navigate(...)} // runs immediately
```

---

## ✅ Correct approach: wrap in handler

```js
function selectMealItemHandler() {
  navigation.navigate('MealDetail', {
    mealId: id,
  });
}
```

Then connect it:

```js
<Pressable onPress={selectMealItemHandler}>
```

---

## 📦 6. Passing data from parent to MealItem

In `MealsOverviewScreen`:

```js
<MealItem
  id={item.id}
  title={item.title}
/>
```

### 💡 Why this matters:

We need the `id` inside `MealItem` to pass it to navigation.

---

## 📥 7. Receiving params in Meal Detail screen

Screen components receive:

- `route` → contains parameters
    
- `navigation` → navigation control
    

```js
function MealDetailScreen({ route }) {
  const mealId = route.params.mealId;

  return <Text>Meal ID: {mealId}</Text>;
}
```

---

## 🔑 Key concepts summary

### 🧭 React Navigation flow

1. Create screen
    
2. Register screen in stack
    
3. Navigate using screen name
    
4. Pass params
    
5. Read params via `route.params`
    

---

### 🔄 Data flow

```
MealsOverview → MealItem → navigation.navigate → MealDetailScreen
                         (mealId passed)              (route.params)
```

---

## ⚠️ Common mistakes

- Forgetting to register the screen in `App.js`
    
- Using wrong screen name in `navigate`
    
- Calling `navigate()` directly instead of inside a function
    
- Not passing required props (like `id`) to child components
    
- Forgetting `route.params`
