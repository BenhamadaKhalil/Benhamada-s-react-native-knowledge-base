# 📱 React Native — Creating a New Project (Expo vs React Native CLI)

## 📂 Section
GETTING STARTED

---

## 🎯 Purpose of This Video
Explain how to **get started with React Native**, where to create projects, and **why Expo is the recommended approach** compared to the React Native CLI.

---

## 🌐 Official Resource

- Official website: https://reactnative.dev
- Useful for:
  - Learning React Native
  - Documentation
  - Project setup
  - Deep dives beyond the course

To create a project:
- Click **Get Started**
- Go to **Setting up the development environment**

---

## 🛠 Two Ways to Create React Native Projects

On the setup page, there are **two main approaches**:

1. **Expo CLI** (default & recommended)
2. **React Native CLI**

Both are **CLI tools** (Command Line Interface).

---

## 🔧 What These Tools Are Used For

Both Expo CLI and React Native CLI allow you to:
- Create new React Native projects
- Run apps on:
  - Real devices
  - Emulators / simulators
- Build apps into **distributable packages**
- Upload apps to **App Store / Google Play**

➡️ You only need **one** of them.

---

## 🚀 Expo (Recommended Approach)

Expo is:
- A **third-party tool**
- Free to use
- No signup required
- Offers optional paid services (not required)

Using Expo gives you a **managed development workflow**, meaning:
- Easier project creation
- Easier development
- Easier access to native features (camera, etc.)
- Less configuration
- Less friction overall

Important:
- Expo is **not just a project creator**
- It also provides:
  - Helpful packages
  - Developer tools
  - APIs that simplify native functionality

---

## 🔁 Flexibility of Expo

- You can **start with Expo**
- You can **leave Expo anytime**
- You can later switch to:
  - Pure React Native CLI workflow

This makes Expo ideal for beginners:
- Easy start
- No lock-in

---

## 🧰 React Native CLI (Alternative)

React Native CLI:
- Provided by the **React Native team & community**
- Existed **before Expo**
- Offers a **bare-bones setup**

Characteristics:
- More manual configuration
- Less convenience
- More setup work
- Native features require more effort

However:
- Easier to integrate **native source code**
  - Java
  - Kotlin
  - Swift
  - Objective-C

This can be useful if:
- You must heavily mix JS with native code

---

## ⚖️ Expo vs React Native CLI (As Explained)

| Aspect | Expo | React Native CLI |
|-----|-----|------------------|
| Setup | Very easy | Manual & longer |
| Workflow | Managed | Bare-bones |
| Native features | Easy access | More work |
| Configuration | Minimal | More required |
| Native code integration | Less direct | Easier |
| Flexibility | Can eject anytime | No Expo layer |
| Recommendation | ✅ Yes (start here) | Advanced use cases |

---

## ✅ Final Decision for This Course

- This course uses **Expo**
- Reasons:
  - Easier to get started
  - Less friction
  - Still flexible
  - Recommended by official docs

The goal of React Native:
- Avoid native code most of the time
- Focus on JavaScript & React

---

## 🧠 Key Takeaways

- reactnative.dev is the main reference
- Two CLIs exist, but you only need one
- Expo simplifies everything
- Expo is free and flexible
- You can switch away from Expo anytime
- Expo is ideal for learning and real apps
