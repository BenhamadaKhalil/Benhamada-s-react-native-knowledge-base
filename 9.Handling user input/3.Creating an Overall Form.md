# 🎬 Using the Custom Input Component in ExpenseForm (React Native)

## 🧠 Core Concept
In this step, we actually **use our reusable `Input` component inside `ExpenseForm`** and fully configure it for different types of user inputs:

- Amount
- Date
- Description

We also start adding **real TextInput configuration (props via config object)**.

---

## 🧱 Using the Custom Input Component

After creating the reusable `Input` component, we now:

### 📌 Step 1: Import and use it

Inside `ExpenseForm.js`:

```js
import Input from './Input';
````

Then use it like any React component:

```jsx
<Input />
<Input />
<Input />
```

👉 One per field:

- Amount
    
- Date
    
- Description
    

---

## 🏷️ Configuring Each Input

We customize each input using props:

---

## 💰 1. Amount Input Configuration

### 📌 Purpose

Capture numeric value (expense amount)

### ⚙️ Config

```js
<Input
  label="Amount"
  textInputConfig={{
    keyboardType: 'decimal-pad',
    onChangeText: amountChangeHandler
  }}
/>
```

---

### 🧠 Key Ideas

- `keyboardType: 'decimal-pad'`
    
    - Opens numeric-friendly keyboard
        
    - Prevents normal text input
        
- `onChangeText`
    
    - Fires every time user types
        
    - Will later update state
        

👉 Right now handler is empty placeholder function.

---

## 📅 2. Date Input Configuration

### 📌 Purpose

Capture date in specific format

### ⚙️ Config

```js
<Input
  label="Date"
  textInputConfig={{
    placeholder: 'YYYY-MM-DD',
    maxLength: 10,
    onChangeText: dateChangeHandler
  }}
/>
```

---

### 🧠 Key Ideas

#### 📌 Placeholder

- Guides user input format
    
- Example:
    
    ```
    YYYY-MM-DD
    ```
    

#### 📌 maxLength: 10

Limits input length:

- 4 (year)
    
- 2 (month)
    
- 2 (day)
    
- 2 dashes
    

👉 Prevents invalid longer input

---

## 📝 3. Description Input Configuration

### 📌 Purpose

Capture free text description of expense

### ⚙️ Config (basic version)

```js
<Input
  label="Description"
  textInputConfig={{
    multiline: true,
    onChangeText: descriptionChangeHandler
  }}
/>
```

---

### 🧠 Key Ideas

- `multiline: true`
    
    - Allows multiple lines of text
        
    - Useful for longer descriptions
        
- `onChangeText`
    
    - Tracks user input
        

---

## ⚙️ Why This Pattern Works

Instead of repeating `TextInput` logic everywhere, we now:

### ✔ Use one reusable component (`Input`)

### ✔ Pass configuration via `textInputConfig`

### ✔ Keep screen clean and readable

---

## 🧩 Mental Model

Think of it like this:

```
ExpenseForm
   ↓
Input (reusable UI wrapper)
   ↓
TextInput (native input engine)
   ↓
User input events → state (later)
```

👉 We are building a **form system, not just inputs**

---

## 🚨 Common Mistakes

- ❌ Forgetting to forward config using `{...textInputConfig}`
    
- ❌ Hardcoding keyboard type in Input component
    
- ❌ Not separating logic (Form vs Input vs Screen)
    
- ❌ Ignoring UX improvements like placeholder or maxLength
    

---

## 🧪 Takeaways

- You can reuse one Input component for many fields
    
- `textInputConfig` makes the component scalable
    
- Different inputs need different configurations
    
- React Native forms are built by combining small reusable pieces
