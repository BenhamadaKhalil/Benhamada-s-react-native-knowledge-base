# 🎬 Prefilling Form Data in Edit Mode (React Native Expense Form)

## 🧠 Core Concept
In this step, we implement **edit mode prefilled forms**, so that when a user edits an existing expense:

- The form automatically shows existing values
- The user does NOT need to retype everything
- We reuse the same form for both Add + Edit

👉 This is a key **real-world UX improvement**

---

## 🔁 1. Fetching the Selected Expense

In `ManageExpense`, we retrieve the expense using its ID:

```js id="findexpense1"
const selectedExpense = expensesContext.expenses.find(
  (expense) => expense.id === editedExpenseId
);
````

---

### 🧠 How it works

- Loop through all expenses
    
- Match by `id`
    
- Return the correct expense object
    

👉 Result: full expense data available for editing

---

## 📦 2. Passing Data to ExpenseForm

We send the selected expense as a prop:

```js
<ExpenseForm defaultValues={selectedExpense} />
```

---

### 🧠 Why this works

- `Add mode` → no defaultValues (undefined)
    
- `Edit mode` → full expense object
    

---

## 🧱 3. Handling Default Values in ExpenseForm

We initialize state using conditional defaults:

---

### 📌 Amount

```js
const [inputValues, setInputValues] = useState({
  amount: defaultValues ? defaultValues.amount.toString() : '',
  date: '',
  description: ''
});
```

---

### 🧠 Why `.toString()`

- Inputs always require strings
    
- Stored data may be numbers
    

---

## 📅 4. Prefilling Date Correctly

### 📌 Problem

We store date as a `Date` object, but input needs a string.

---

### 📌 Solution: format to YYYY-MM-DD

```js
defaultValues
  ? getFormattedDate(defaultValues.date)
  : ''
```

---

### 📦 Using utility function

We reuse a helper:

```js
getFormattedDate(date);
```

---

### 🧠 Why this is important

- Ensures consistent formatting
    
- Avoids duplicated logic
    
- Keeps UI predictable
    

---

## 📝 5. Prefilling Description

```js
description: defaultValues ? defaultValues.description : ''
```

---

### 🧠 Simple case

- Already a string → no transformation needed
    

---

## 🔁 6. Full State Initialization Pattern

```js
const [inputValues, setInputValues] = useState({
  amount: defaultValues ? defaultValues.amount.toString() : '',
  date: defaultValues ? getFormattedDate(defaultValues.date) : '',
  description: defaultValues ? defaultValues.description : ''
});
```

---

## ⚙️ 7. UX Behavior Achieved

### 📌 Add Mode

- defaultValues = undefined
    
- All inputs empty
    

### 📌 Edit Mode

- defaultValues exists
    
- Inputs prefilled with real data
    

---

## 🧠 Mental Model

Think of this as:

```text
Mode Detection (Add / Edit)
        ↓
Fetch existing expense (if edit)
        ↓
Pass as defaultValues
        ↓
Initialize form state
        ↓
Inputs reflect state automatically
```

---

## 🚨 Common Mistakes

- ❌ Forgetting `.toString()` for numeric inputs
    
- ❌ Passing raw Date objects into TextInput
    
- ❌ Not handling `undefined` defaultValues
    
- ❌ Duplicating formatting logic instead of using helper
    
- ❌ Mixing Add/Edit logic in multiple places
    

---

## 🧪 Takeaways

- Use `find()` to retrieve selected expense
    
- Pass `defaultValues` into form
    
- Initialize state based on mode (Add vs Edit)
    
- Convert types properly:
    
    - number → string
        
    - date → formatted string
        
- Reuse utility functions for formatting
    

---
