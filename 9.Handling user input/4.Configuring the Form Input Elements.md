# 🎬 Configuring the Description Input (TextInput Advanced Props)

## 🧠 Core Concept
In this step, we fine-tune the **Description input field** in our `ExpenseForm` by using advanced `TextInput` props.

The goal is to improve **user experience (UX)** when entering longer text.

---

## 🧱 Key Configuration for Description Input

Unlike Amount or Date, the Description field:
- Allows free text
- Supports multiple lines
- Needs smart typing behavior (not restrictive input rules)

---

## 📄 1. Multiline Input

### 📌 Purpose
Allow users to enter **multiple lines of text**

### ⚙️ Prop

```js id="h9k3aa"
multiline: true
````

---

### 🧠 What it does

- Expands input into a textarea-like field
    
- Makes pressing "Enter" create a new line
    
- Improves usability for longer descriptions
    

👉 On Android, you can also use:

- `numberOfLines` (optional constraint on visible lines)
    

---

## 🔤 2. autoCorrect

### 📌 Purpose

Controls automatic spelling correction while typing

### ⚙️ Default behavior

```js
autoCorrect: true
```

---

### ⚠️ Important Insight

AutoCorrect can be:

- ✅ Helpful → for normal text input (like descriptions)
    
- ❌ Annoying → for emails, usernames, codes
    

Example problem:

- You type something correctly
    
- Device "corrects" it incorrectly 😤
    

---

### 📌 In this case (Description field)

We keep default behavior:

```js
// autoCorrect: true (default, not required to set)
```

👉 Because:

- Descriptions are natural language
    
- Spelling correction improves readability
    

---

## 🔠 3. autoCapitalize

### 📌 Purpose

Controls automatic capitalization behavior

---

### ⚙️ Options

|Value|Behavior|
|---|---|
|`none`|No auto-capitalization|
|`sentences`|Capitalize first letter of sentences (default)|
|`words`|Capitalize each word|
|`characters`|Capitalize all letters|

---

### 📌 In this app

We keep default:

```js
autoCapitalize: 'sentences'
```

---

### 🧠 When to change it

- ❌ Email fields → `none`
    
- ❌ Usernames → `none`
    
- ❌ Codes / passwords → `none`
    
- ✅ Description → `sentences` (good UX)
    

---

## 🧩 Final Description Input Example

```js
<Input
  label="Description"
  textInputConfig={{
    multiline: true,
    autoCorrect: true,
    autoCapitalize: 'sentences',
    onChangeText: descriptionChangeHandler
  }}
/>
```

---

## ⚙️ Mental Model

Think of `TextInput` behavior like layers:

- 🧾 Input type → single-line vs multiline
    
- ✍️ Typing assistance → autoCorrect
    
- 🔤 Formatting rules → autoCapitalize
    

👉 Together they define the **typing experience**, not just data entry.

---

## 🚨 Common Mistakes

- ❌ Using `autoCorrect` for emails or passwords
    
- ❌ Forgetting `multiline` for long text fields
    
- ❌ Over-customizing capitalization unnecessarily
    
- ❌ Not considering UX impact of default keyboard behavior
    

---

## 🧪 Takeaways

- `multiline: true` improves long text input UX
    
- `autoCorrect` can help or annoy depending on context
    
- `autoCapitalize` controls text formatting behavior
    
- Defaults are often good — but context matters
    

---

## ⚡ Quick Summary

- Add `multiline: true` for description input
    
- Keep `autoCorrect` enabled (default)
    
- Keep `autoCapitalize: 'sentences'`
    
- Understand when to disable these props in other forms
    
- Focus on UX, not just functionality
