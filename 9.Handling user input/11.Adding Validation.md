# 🎬 Form Validation on Submit (React Native Expense Form)

## 🧠 Core Concept
In this step, we add **form validation at submission time**.

Instead of validating on every keystroke, we:

- Validate only when user presses "Submit"
- Prevent invalid data from being sent
- Provide user feedback if validation fails

👉 This is a common real-world pattern for forms

---

## ⚙️ 1. Validation Strategy

We validate inside:

```js id="submitvalidate1"
submitHandler()
````

before creating / sending `expenseData`.

---

## 🔢 2. Amount Validation

### 📌 Rules:

- Must be a number
    
- Must be greater than 0
    

```js
const amountIsValid =
  !isNaN(expenseData.amount) && expenseData.amount > 0;
```

---

### 🧠 Explanation

- `isNaN()` checks if value is NOT a number
    
- We invert logic to ensure validity
    
- Must also be positive (> 0)
    

---

## 📅 3. Date Validation

### 📌 Trick: Detect Invalid Date

JavaScript behavior:

```js
new Date('invalid') → Invalid Date
```

So we check:

```js
const dateIsValid =
  expenseData.date.toString() !== 'Invalid Date';
```

---

### 🧠 Why this works

- Invalid Date becomes string `"Invalid Date"`
    
- Valid dates produce readable string
    
- We invert logic to get `true` when valid
    

---

## 📝 4. Description Validation

### 📌 Rule:

- Must not be empty
    
- Ignore whitespace
    

```js
const descriptionIsValid =
  expenseData.description.trim().length > 0;
```

---

### 🧠 Why `.trim()` matters

Prevents:

- `" "` (spaces only)
    
- Empty strings
    
- Fake input
    

---

## 🧱 5. Combined Validation Check

We stop submission if ANY field is invalid:

```js
if (
  !amountIsValid ||
  !dateIsValid ||
  !descriptionIsValid
) {
  Alert.alert('Invalid input', 'Please check your input values!');
  return;
}
```

---

## 🚨 6. Using Alert for Feedback

We use React Native’s built-in API:

```js
import { Alert } from 'react-native';

Alert.alert(
  'Invalid input',
  'Please check your input values!'
);
```

---

### 🧠 Why Alert is used here

- Simple immediate feedback
    
- Blocks submission
    
- Good for initial implementation
    

---

## 🔁 7. Full Validation Flow

```text
User presses submit
   ↓
expenseData created
   ↓
Validation runs:
   - amountIsValid
   - dateIsValid
   - descriptionIsValid
   ↓
If invalid → show Alert + stop
If valid → submit to context
```

---

## 🧠 Mental Model

Think of validation as a gate:

```text
Input Data → Validation Gate → Context / Storage
```

- ❌ Fails → show error
    
- ✅ Passes → continue flow
    

---

## 🚨 Common Mistakes

- ❌ Validating on every keystroke unnecessarily
    
- ❌ Forgetting `trim()` for text inputs
    
- ❌ Not checking `isNaN()` properly
    
- ❌ Accepting invalid Date objects
    
- ❌ Letting invalid data reach context/state
    

---

## 🧪 Takeaways

- Validate only on submit (for now)
    
- Always check:
    
    - Numbers → `!isNaN` + > 0
        
    - Dates → `"Invalid Date"` check
        
    - Strings → `.trim().length > 0`
        
- Stop execution early using `return`
    
- Provide feedback using `Alert`
