# 🎬 Validation UI Styling (Highlighting Invalid Inputs)
## 🧠 Core Concept
We now improve UX by visually indicating invalid inputs:

- ❌ Error message styling
- ❌ Red label for invalid fields
- ❌ Red-ish background for invalid inputs
- ✔️ Immediate visual feedback inside form

👉 This is **production-level form UX**

---

## 🎨 1. Styling the Error Message

We define a dedicated style:

```js id="errorstyle1"
errorText: {
  textAlign: 'center',
  color: GlobalStyles.colors.error500,
  margin: 8
}
````

---

### 🧠 Purpose

- Center the message
    
- Use red error color
    
- Add spacing for readability
    

---

## 🧾 2. Applying Error Text Style

```js
<Text style={styles.errorText}>
  Invalid input values - please check your data!
</Text>
```

---

## ⚠️ 3. Passing Validation State to Input Component

We send an `invalid` prop from `ExpenseForm` → `Input`:

```js
<Input
  invalid={!inputs.amount.isValid}
/>
```

---

### 📌 Logic

```text
isValid = true  → invalid = false
isValid = false → invalid = true
```

---

## 🎯 4. Why Invert the Value?

We pass:

```js
invalid = !inputs.amount.isValid
```

Because:

- UI cares about "invalid state"
    
- State stores "valid state"
    

---

## 🎨 5. Input Component Styling Strategy

We define conditional styles in `Input.js`

---

### 📌 Invalid Label Style

```js
invalidLabel: {
  color: GlobalStyles.colors.error500
}
```

---

### 📌 Invalid Input Style

```js
invalidInput: {
  backgroundColor: GlobalStyles.colors.error50
}
```

---

## 🔁 6. Conditional Styling Logic

### 📌 Label

```js
<Text
  style={[
    styles.label,
    invalid && styles.invalidLabel
  ]}
>
```

---

### 📌 Input Field

```js
<TextInput
  style={[
    styles.input,
    invalid && styles.invalidInput
  ]}
/>
```

---

## 🧠 Why This Pattern Works

- Always applies base style
    
- Adds error style only if needed
    
- Keeps UI declarative and clean
    

---

## 🔄 7. Live Validation Behavior

### 📌 What happens:

|Action|Result|
|---|---|
|User types|field becomes valid|
|Invalid submit|field turns red|
|Fix input|red disappears|
|Submit again invalid|red returns|

---

## 🧠 8. Important UX Insight

This system is:

### ✔️ Optimistic during typing

- Assumes user input is valid while typing
    

### ✔️ Strict on submit

- Re-validates everything on submit
    

---

## ⚠️ 9. Common Pitfalls

- ❌ Forgetting to invert `isValid` → `!isValid`
    
- ❌ Overwriting full style instead of merging
    
- ❌ Not preserving base styles
    
- ❌ Showing error state too early
    
- ❌ Mixing UI state and data state incorrectly
    

---

## 🧪 Takeaways

- Add `invalid` prop to inputs
    
- Use conditional styling with arrays
    
- Separate base styles + error styles
    
- Use red theme for invalid fields
    
- Keep UX responsive and dynamic
    

---

## ⚡ Final Mental Model

```text
Validation State (isValid)
        ↓ invert
UI State (invalid)
        ↓
Conditional Styles Applied
        ↓
User sees feedback instantly
```
