# 📱 React Native — Handling User Input & Button Press (Events + State)

## 🎯 What problem are we solving?

Right now the UI looks OK, but it’s “dead”:

- You can type in `TextInput`
    
- You can tap the `Button`
    
- **But nothing happens**, because we didn’t connect any **events** to any **logic**
    

Just like React on the web, React Native apps only react when you:

1. **Listen to events** (input change, press, etc.)
    
2. **Run handler functions**
    
3. **Store data in state** so it can be used later
    

---

## ✅ Key idea: React Native = React logic (same core)

Even though this is a mobile app (React Native instead of React DOM), **React’s core features are identical**:

- Event handlers (functions)
    
- `useState` for state
    
- Updating state triggers re-render
    

The difference is mainly the **event prop names** (e.g. `onPress` instead of `onClick`).

---

# 1) Handling text input: `onChangeText`

## Why do we need it?

We want to capture what the user types **as they type**.

React Native provides a special prop on `TextInput`:

```jsx
onChangeText={goalInputHandler}
```

### Important: `onChangeText` gives you the text automatically

Your handler receives one parameter: the current typed text.

```jsx
function goalInputHandler(enteredText) {
  console.log(enteredText);
}
```

### What happens when typing "Test"

As you type:

- T
    
- Te
    
- Tes
    
- Test
    

The handler runs **each keystroke**, logging each intermediate value.

---

## ⚠️ Very important: Don’t call the function in JSX

✅ Correct (pass a function reference):

```jsx
onChangeText={goalInputHandler}
```

❌ Wrong (executes immediately during render):

```jsx
onChangeText={goalInputHandler()}
```

**Mental model:**  
React Native says: “I will call your function later when the event happens.”  
So you **hand it the function**, you don’t run it yourself.

---

# 2) Handling the button: `onPress`

In web React you’d do `onClick`, but in mobile it’s not a click, it’s a **press/tap**.

React Native uses:

```jsx
<Button title="Add Goal" onPress={addGoalHandler} />
```

Same rule applies:

✅

```jsx
onPress={addGoalHandler}
```

❌

```jsx
onPress={addGoalHandler()}
```

---

# 3) Why state is needed (connecting the two events)

We have two separate moments:

1. User types → `goalInputHandler` runs
    
2. User presses button → `addGoalHandler` runs
    

But the typed value must be available when the button is pressed.

If we only `console.log(enteredText)` inside `goalInputHandler`, that value is “stuck” in that function call.

✅ Solution: store the typed value in **state**.

---

# 4) Using `useState` to store typed text

We import `useState` from **react** (not react-native):

```jsx
import { useState } from 'react';
```

Create state inside the component:

```jsx
const [enteredGoalText, setEnteredGoalText] = useState('');
```

- `enteredGoalText` → current value
    
- `setEnteredGoalText` → function to update it
    
- initial value is `''` (empty string)
    

---

## Update state on every keystroke

```jsx
function goalInputHandler(enteredText) {
  setEnteredGoalText(enteredText);
}
```

Now the latest typed text is always stored in state.

---

## Use state when button is pressed

```jsx
function addGoalHandler() {
  console.log(enteredGoalText);
}
```

So the flow becomes:

**Typing updates state → pressing reads state.**

---

# ✅ Final code (exact pattern used in the lecture)

```jsx
import { useState } from 'react';
import { View, TextInput, Button } from 'react-native';

export default function App() {
  const [enteredGoalText, setEnteredGoalText] = useState('');

  function goalInputHandler(enteredText) {
    setEnteredGoalText(enteredText);
  }

  function addGoalHandler() {
    console.log(enteredGoalText);
  }

  return (
    <View>
      <TextInput
        placeholder="Your course goal"
        onChangeText={goalInputHandler}
      />
      <Button title="Add Goal" onPress={addGoalHandler} />
    </View>
  );
}
```

## 🧠 Mental model you’ll reuse everywhere

**Event → Handler → State → Use state somewhere else**

Example in one line:

- `TextInput` changes → update `enteredGoalText`
    
- Button pressed → use `enteredGoalText`
