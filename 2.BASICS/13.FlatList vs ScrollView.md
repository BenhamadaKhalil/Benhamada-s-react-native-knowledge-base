# 📱 React Native — FlatList vs ScrollView (Efficient Lists)

## 🎯 Concept

In React Native, both **ScrollView** and **FlatList** allow scrolling content.

However, they are designed for **different use cases**:

- **ScrollView → small, fixed content**
    
- **FlatList → large, dynamic lists (recommended for lists)**
    

The key difference is **performance and rendering behavior**.

---

## ⚠️ Why ScrollView is NOT good for large lists

ScrollView renders **ALL items at once**, even those not visible on screen.

Example:

```
ScrollView with 1000 items
```

Even if only 10 items are visible, React Native renders all 1000.

This causes:

- ❌ High memory usage
    
- ❌ Slow performance
    
- ❌ Laggy app
    

---

## 📊 How ScrollView works

```
Screen shows:     Item 1
                  Item 2
                  Item 3
                  Item 4

Behind the scenes:
ScrollView renders Item 1 → Item 1000 immediately
```

Everything is loaded immediately.

---

## 🚀 FlatList — The optimized solution

FlatList is designed specifically for lists.

It uses **lazy rendering**.

This means:

- Only visible items are rendered
    
- Other items load when needed
    
- Improves performance significantly
    

---

## 📊 How FlatList works

```
Screen shows:     Item 1
                  Item 2
                  Item 3
                  Item 4

Behind the scenes:
FlatList renders only Item 1 → Item 10

When user scrolls:
FlatList renders Item 11 → Item 20
```

This is called:

> Virtualization / Lazy Loading

---

## ✅ When to use ScrollView

Use ScrollView for:

- Articles
    
- Static content
    
- Small amount of elements
    

Example:

```
Terms and Conditions screen
Profile screen
Settings screen
```

---

## ✅ When to use FlatList (MOST IMPORTANT)

Use FlatList for:

- Lists of data
    
- Dynamic lists
    
- Unknown list size
    
- Large lists
    
- Data from APIs
    

Example:

```
Messages list
Goals list
Products list
Users list
Comments list
```

# 🧠 Basic FlatList Usage

## Step 1 — Replace ScrollView

```
<FlatList />
```

---

## Step 2 — Provide data prop

data = array of items

```
<FlatList data={courseGoals} />
```

Example data:

```
[
  { text: "Learn React Native", key: "1" },
  { text: "Build apps", key: "2" }
]
```

---

## Step 3 — Provide renderItem prop

renderItem tells FlatList how to render each item.

```
<FlatList
  data={courseGoals}
  renderItem={(itemData) => {
    return <Text>{itemData.item.text}</Text>;
  }}
/>
```

---

## 🧠 Important: itemData structure

FlatList gives an object like:

```
itemData = {
   item: yourData,
   index: number
}
```

Example:

```
itemData.item.text
itemData.index
```

---

# 🔑 Keys in FlatList

Keys are required for list performance.

There are 2 methods:

---

## Method 1 — Add key property to data (Recommended)

Example:

```
const [goals, setGoals] = useState([
  { text: "Learn React Native", key: "1" },
  { text: "Build apps", key: "2" }
]);
```

FlatList automatically uses key.

```
<FlatList
  data={goals}
  renderItem={(itemData) => (
    <Text>{itemData.item.text}</Text>
  )}
/>
```

---

## Method 2 — Use keyExtractor prop

Use this if your data has id instead of key.

Example data:

```
[
  { id: "g1", text: "Learn React Native" },
  { id: "g2", text: "Build apps" }
]
```

Use keyExtractor:

```
<FlatList
  data={goals}
  renderItem={(itemData) => (
    <Text>{itemData.item.text}</Text>
  )}
  keyExtractor={(item, index) => item.id}
/>
```

FlatList will use id as key.

---

# ⚡ Full Example (Real World)

```
import { FlatList, Text } from "react-native";

<FlatList
  data={goals}
  renderItem={(itemData) => (
    <Text>{itemData.item.text}</Text>
  )}
/>
```

# ⚡ Real Example with View styling

```
<FlatList

    <View>
      <Text>{itemData.item.text}</Text>
    </View>

```

# 💡 Why FlatList is faster

Because it uses:

- Lazy loading
    
- Virtual rendering
    
- Memory optimization
    

This makes it scalable.

# 🚨 Common mistakes

### ❌ Using ScrollView for large lists

Bad:

```
<ScrollView>
  {items.map(...)}
</ScrollView>
```

---

### ❌ Forgetting key or keyExtractor

Causes warning:

```
Missing keys for items
```

---

### ❌ Using primitive values instead of objects

Bad:

```
["Goal 1", "Goal 2"]
```

Good:

```
[{ text: "Goal 1", key: "1" }]
```
