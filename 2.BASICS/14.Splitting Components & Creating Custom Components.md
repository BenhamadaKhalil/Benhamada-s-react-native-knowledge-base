# 📱 React Native — Splitting Components & Creating Custom Components

## 🎯 Concept

As your app grows, your main component (like `App.js`) becomes **large and difficult to manage**.

Best practice in React Native (and React in general):

> Split your UI into **smaller, reusable components**

This improves:

- Readability
    
- Maintainability
    
- Reusability
    
- Scalability
    

---

## ⚠️ Why splitting components is important

Bad approach (everything in one file):

```
App.js
 ├ input logic
 ├ list logic
 ├ styling
 ├ rendering items
 ├ rendering input
 ├ handling events
```

This becomes:

- Hard to read
    
- Hard to debug
    
- Hard to maintain
    

---

## ✅ Good approach (component-based architecture)

Split into smaller components:

```
App.js
components/
   GoalItem.js
   GoalInput.js
```

Each component has **one responsibility**.

---

# 📁 Recommended Folder Structure

```
project/
│
├ App.js
│
├ components/
│   ├ GoalItem.js
│   ├ GoalInput.js
```

Convention: use `components` folder.

---

# 🧠 Creating your first custom component

Example: GoalItem.js

```
function GoalItem() {
   return (
      <View>
         <Text>Goal Item</Text>
      </View>
   );
}

export default GoalItem;
```

This is a **functional component**.

---

## ⚡ Important: No need to import React anymore

Old React:

```
import React from "react";
```

Modern React Native:

```
Not required anymore
```

React automatically handles it.

---

# 📦 Using the component in App.js

Import it:

```
import GoalItem from "./components/GoalItem";
```

Use it in JSX:

```
<GoalItem />
```

This is exactly like built-in components:

```
<View />
<Text />
<Button />
```

But this is your own component.

---

# 🔠 Important rule: Component names must start with CAPITAL letter

Correct:

```
GoalItem
```

Wrong:

```
goalItem
```

Reason:

React uses capital letter to detect custom components.

---

# 🎯 Real Example with FlatList

Before (bad):

```
renderItem={(itemData) => (
  <View>
     <Text>{itemData.item.text}</Text>
  </View>
)}
```

After (good):

```
renderItem={(itemData) => (
   <GoalItem />
)}
```

Cleaner and reusable.

---

# 🎨 Styling inside components

Each component should have its own styles.

Example GoalItem.js:

```
import { View, Text, StyleSheet } from "react-native";

function GoalItem() {
   return (
      <View style={styles.goalItem}>
         <Text style={styles.goalText}>Goal</Text>
      </View>
   );
}

export default GoalItem;

const styles = StyleSheet.create({
   goalItem: {
      backgroundColor: "#5e0acc",
      padding: 10,
      margin: 8,
   },
   goalText: {
      color: "white"
   }
});
```

---

## 💡 Best practice: Keep styles close to component

Bad:

```
All styles in App.js
```

Good:

```
GoalItem.js
   component
   styles
```

This improves maintainability.

---

# 🧠 Component Responsibility Principle

Each component should do ONE thing.

Example:

GoalItem.js → displays one goal

GoalInput.js → handles input

App.js → manages state and logic

---

# 📊 Architecture Flow

```
App.js
 │
 ├ GoalInput.js
 │
 ├ FlatList
      │
      ├ GoalItem.js
      ├ GoalItem.js
      ├ GoalItem.js
```

App controls logic

Components control UI

```

```

Each component handles specific UI.

---

# 🚨 Common mistakes

### ❌ Putting everything in App.js

Hard to maintain.

---

### ❌ Not exporting component

Wrong:

```
function GoalItem() {}
```

Correct:

```
export default GoalItem;
```

---

### ❌ Not importing component

Must import before using:

```
import GoalItem from "./components/GoalItem";
```

---

# 🧠 Summary

React Native apps use multiple components.

Best practice:

- Split large components
    
- Create reusable components
    
- Store in components folder
    
- Each component has its own styles
    
- Import and use components in App.js
    

This makes your app:

- Clean
    
- Scalable
    
- Professional
