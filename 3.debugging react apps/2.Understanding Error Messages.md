# 🐛 React Native — Understanding Error Messages (Image source example)

## 🎯 Concept

Error messages are one of your most important debugging tools.

They help you understand:

- What went wrong
    
- Where it went wrong
    
- Which component caused the error
    

Learning to read error messages correctly is a critical skill.

---

# 🧪 Example: Forcing an Error in the Image component

Correct usage of Image:

```
<Image source={require("../assets/images/goal.png")} />
```

Forced error example:

```
<Image source={"invalid-path"} />
```

This is incorrect in React Native.

Result:

React Native shows an error message.

---

# ⚠️ Example Error Message Explained

Error message:

```
Invalid prop 'source' supplied to Image
Expected type number
```

This tells you:

- The problem is with the `source` prop
    
- The Image component expected a valid image reference
    
- The provided value is invalid
    

---

# 🧠 Important Lesson: Error messages may be confusing

Some parts of error messages can be unclear.

Example:

```
Expected type number
```

This refers to how React Native internally handles images.

Even if confusing, focus on:

```
Invalid prop 'source'
```

This clearly points to the problem.

---

# 📍 Stack Trace — The Most Important Debugging Tool

Error messages include a stack trace.

Example stack trace:

```
Image
GoalInput
App
```

This tells you the component hierarchy.

Meaning:

```
Error occurred in Image
inside GoalInput
inside App
```

This helps you locate the exact file.

---

# 🧭 How to use stack trace effectively

Always look for YOUR component names.

Example:

```
GoalInput
```

This tells you:

```
GoalInput.js
```

is where the problem exists.

Not the internal React Native code.

---

# 📱 Error Messages Locations

React Native shows errors in multiple places:

---

## 1. Terminal (Most useful)

Shows:

- Error description
    
- Stack trace
    
- File references
    

Example location:

```
Terminal window
```

---

## 2. Emulator error overlay

Shows error inside app screen.

Example:

```
Red error screen
```

Includes:

- Error message
    
- Stack trace
    

---

## 3. Emulator warning panel

Shows warnings at bottom.

Warnings mean:

- App still runs
    
- But behavior is incorrect
    

Example warning:

```
Invalid image source
```

Image won’t display, but app continues running.

---

# ⚠️ Error vs Warning difference

Error:

- App crashes
    
- Must fix immediately
    

Warning:

- App still runs
    
- But something is wrong
    

Example:

```
Invalid image path → warning
```

# 🧠 Debugging Process Example

Error appears:

```
Invalid prop 'source'
```

Steps to fix:

1. Read error message
    
2. Identify component → GoalInput
    
3. Open GoalInput.js
    
4. Find Image component
    
5. Check source prop
    
6. Fix using require()
    

---

# 🧠 Key Debugging Mindset

Always follow this process:

```
Read error message
↓
Check stack trace
↓
Find your component
↓
Locate problem code
↓
Fix code
↓
Test again
```

---

# 🚨 Common mistake with Image component

Wrong:

```
<Image source="path/to/image.png" />
```

Correct:

```
<Image source={require("../assets/images/image.png")} />
```

# 🧠 Summary

Error messages provide critical debugging information.

Always check:

- Error description
    
- Stack trace
    
- Component names
    

Stack trace helps identify:

- Which file caused the error
    
- Which component is involved
    

Use documentation when unsure.

Understanding error messages helps you debug faster and build apps more efficiently.
