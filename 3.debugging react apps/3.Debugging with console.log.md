# 🐛 React Native — Debugging with console.log

## 🎯 Concept

Sometimes your app has **no errors**, but you still want to understand:

- When components render
    
- When functions execute
    
- What values variables or state contain
    

For this, you use:

```
console.log()
```

This is one of the simplest and most powerful debugging tools.

---

# 🧠 Basic usage

You can log anything:

```
console.log("GoalInput component rendered");
```

This message will appear in the terminal.

---

# 📍 Where console.log output appears

Logs appear in the terminal where you ran:

```
npm start
```

Example output:

```
GoalInput component rendered
```

If running multiple emulators:

```
GoalInput component rendered
GoalInput component rendered
```

One log per device.

---

# 🧠 Why console.log is useful

It helps you understand:

- Execution flow
    
- Component rendering
    
- Function calls
    
- State changes
    

---

# 🧪 Example 1 — Log when component renders

GoalInput.js:

```
function GoalInput(props) {

   console.log("GoalInput component rendered");

   return (...);
}
```

Output:

```
GoalInput component rendered
```

Every time component renders.

---

# 🧪 Example 2 — Log user input value

Inside input handler:

```
function goalInputHandler(text) {

   console.log(text);

   setEnteredGoalText(text);

}
```

Terminal output when typing:

```
H
He
Hel
Hell
Hello
```

Shows real-time state changes.

---

# 📊 Debugging execution flow example

```
User types text
↓
goalInputHandler executes
↓
console.log prints text
↓
State updates
↓
Component re-renders
↓
console.log prints render message
```

---

# 🧠 Where to use console.log

Common places:

### Inside components

```
console.log("Component rendered");
```

---

### Inside event handlers

```
function handler() {
   console.log("Button pressed");
}
```

---

### Inside state updates

```
console.log(goals);
```

---

### Inside functions

```
function deleteGoalHandler(id) {
   console.log("Deleting:", id);
}
```

---

# 📊 Example debugging Goal App

```
function addGoalHandler(text) {
```

Output:

```
Adding goal: Learn React Native
```

---

# 🧠 Debugging render frequency

Sometimes components re-render unexpectedly.

Example:

```
console.log("GoalItem rendered");
```

Helps detect unnecessary renders.

---

# 🧠 Debugging state values

Example:

```
console.log(courseGoals);
```

Output:

```
[
  { text: "Learn React Native", id: "g1" },
  { text: "Build Apps", id: "g2" }
]
```

---

# 🚨 Important: console.log does NOT affect app behavior

It only prints information.

Safe to use during development.

---

# ⚠️ Remove console.log in production

Too many logs:

- Slow performance
    
- Clutter output
    

Use only for debugging.

---

# 🧠 Terminal vs Browser Console

React Web:

```
console.log → browser console
```

React Native:

```
console.log → terminal
```

Because there is no browser.

---

# 🧠 Debugging mindset using console.log

When something is wrong, log:

- Function execution
    
- Variable values
    
- State values
    

Example process:

```
console.log("Function started");
console.log(variable);
console.log(state);
```

Find where logic breaks.

---

# 🧠 Summary

console.log is essential for debugging.

It helps:

- Track execution flow
    
- Inspect variables
    
- Inspect state
    
- Understand component behavior
    

Logs appear in the terminal when using React Native.

console.log is one of the most important debugging tools.
